# Milestones

## 1. 企画と前提の固め
- 目的: 「待ちなし」の価値と対象ユーザーを再確認する
- 内容:
  - エレベーターピッチを最終化する
  - ユースケースを 3〜5 個にまとめる
  - 作らないものを明確にしてスコープを固定する
  - MVP の対象ユーザーを 1 つに絞る
- 完了の目安:
  - scope.md と整合している
  - 「何を作るか」「何を作らないか」が説明できる

## 2. MVP の対象を定義する
- 目的: まずは最小で検証できる体験を決める
- 内容:
  - 1 つの核心ユースケースを選ぶ
  - そのユースケースで使う画面とアクションを整理する
  - 主要な入力と出力を定義する
- 完了の目安:
  - 「相手に連絡が来ないときに、安心確認を送る」体験が一連の流れとして説明できる

## 3. UI とフローの設計
- 目的: 画面の体験を具体化する
- 内容:
  - ログイン／未ログインの導線を整理する
  - 連絡待ちの状態を表示する画面を設計する
  - テンプレート選択・送信確認・履歴閲覧の流れを作る
- 完了の目安:
  - 1 つのユーザー導線が、紙でも描けるレベルで整理できている

## 4. 1 週間のプロトタイプを作る
- 目的: 体験の妥当性を早く確かめる
- 内容:
  - 最小限の画面と遷移を実装する
  - 送信後の確認状態を再現する
  - 一連のフローが実際に動くか検証する
- 完了の目安:
  - 「確認テンプレートを選んで送る」までが実際に操作できる

## 5. 使い心地の改善と伝わりの検証
- 目的: 初回体験で離脱しないようにする
- 内容:
  - 画面の文言を簡潔にする
  - どこで迷うかを洗い出す
  - 送信前後の安心感が伝わるかを見直す
- 完了の目安:
  - 体験の説明が短く、ユーザーが「使ってみたい」と感じる状態になる

## 6. MVP の検証と次の改善候補
- 目的: 次の一手を決める
- 内容:
  - 実際に使う人に確認する
  - どこで価値を感じたかを整理する
  - 使わない／離脱した箇所を拾う
  - 次の改善項目を優先順位付きでまとめる
- 完了の目安:
  - 次の改善が 3〜5 個までに整理できる
  - リリース可否の判断ができる

## ざっくりした実行計画

### Phase 1: 1 〜 2 週間
- scope の確定
- ユースケース整理
- MVP の対象ユーザー固定

### Phase 2: 3 〜 4 週間
- UI とユーザー導線の設計
- 最低限のプロトタイプ実装
- 初回体験の確認と修正

### Phase 3: 5 〜 6 週間
- 検証
- 改善
- 次のリリース候補を整理

## 最終的な目標
- 「待ち合わせの不安を減らす」という最小価値を持つ MVP を作る
- 使う人にとって一瞬で価値が伝わる体験を作る
- そこから、次に必要な機能追加や改善の判断材料を集める
